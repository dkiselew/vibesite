# Ускорение HTML-правок

**Статус:** идеи, не контракт. В переход на удалённый MCP не входит. Пока правка — полный `put` HTML после `get_document`.

Сейчас модель читает всю страницу и присылает её целиком. На длинной странице она чаще переписывает документ, тратит токены на неизменённую разметку и портит соседние теги. Ниже способы вернуть точечность локального файла. На диске по-прежнему один HTML. Второй сохранённой копии markdown нет.

## Точечная замена

`patch_document` меняет один фрагмент сохранённого HTML. Модель присылает кусок, который уже видела в `get_document`, а не всю страницу. Markdown-шаблон здесь не участвует.

Чтение страницы остаётся полным: чтобы скопировать `old`, модель один раз вызывает `get_document`. Выигрыш на записи. Модель не переписывает неизменённую разметку.

Тул садится рядом с записью HTML и не затрагивает запись markdown. Повторный markdown на то же имя по-прежнему прогоняет шаблон и стирает ручные HTML-правки.

### Вызов

Один вызов — одна замена.

- `name` — та же грамматика, что у остальных тулов. Хвостовой `.html` или `.md` снимается и формат не выбирает.
- `old` — непустая строка. Сравнение буквальное: те же символы, пробелы и переносы, что в поле `html` ответа `get_document`. Регистр значим. Это не регулярное выражение и не поиск по DOM.
- `new` — строка замены. Пустая строка удаляет `old`.
- `hash` — необязательный SHA-256 в hex из `get_document`. Если передан и не совпал с текущим телом, запись не делается.

Несколько правок в разных местах — несколько вызовов. Пока `old` следующей правки не задет предыдущей, повторный `get_document` не нужен: поиск идёт по уже записанному телу. Если следующий фрагмент пересекается с уже заменённым, модель берёт свежий `get_document`.

### Шаги на сервере

Чистая функция `applyExactPatch(html, old, replacement)` отдельно от записи. Запись загружает документ, сверяет хеш и кладёт результат тем же путём, что полная замена HTML. Тот же `id`, лимит числа документов не проверяется.

1. Нормализовать `name`. Ошибка грамматики — `invalid_name`.
2. Прочитать документ. Нет объекта — `not_found`, тело не меняется.
3. Если `hash` передан, сравнить его с SHA-256 текущего тела. Не совпал — код `conflict`, статус 409. Модель правила снимок, который уже заменили.
4. Отклонить пустой `old` кодом `bad_request`. Пустой поиск совпал бы с каждым местом между символами.
5. Посчитать вхождения через `indexOf` в цикле, без `RegExp`. Ноль вхождений — `patch_not_found`, статус 400. Больше одного — `patch_ambiguous`, статус 400. Сообщение просит расширить `old` соседними символами, пока совпадение не станет единственным. В обоих случаях тело остаётся прежним.
6. Если `old` и `new` равны, вернуть текущую сводку и не писать. `updated_at` не сдвигается.
7. Собрать новую строку одним разрезом: символы до индекса, `new`, символы после `old`.
8. Проверить результат отдельно от обёртки фрагмента. Пустое после `trim` — `invalid_html`. UTF-8 длиннее лимита документа — `limit_exceeded`. Обёртку фрагмента не вызывать: у уже сохранённой страницы есть `<html`, а обёртка при отсутствии тега вкладывает страницу в новый каркас. Правка `<title>` или шапки не должна это делать.
9. Записать с тем же `id`.
10. Вернуть `id`, `name`, `url`, `updated_at`, `bytes`. Поле `html` в ответ не класть.

`not_found` остаётся только про отсутствующий документ. `patch_not_found` — про отсутствующий фрагмент.

`hash` — hex SHA-256 байтов тела в UTF-8, тем же подсчётом, что лимит размера. Считается при чтении, в хранилище не пишется. `get_document` начинает отдавать его вместе с оригиналом.

### Чего не делать в первой версии

Сервер не схлопывает пробелы, не парсит теги и не выбирает «похожее» место. Любая нормализация разведёт строку модели и строку на диске, и правильный фрагмент получит `patch_not_found`. Модель копирует `old` из `html`.

Один вызов не принимает массив правок. Атомарная пачка ускорила бы несколько замен, но ошибка посередине требует решать, откатывать ли уже проверенные куски. Каждая замена сама по себе атомарна: при ошибке документ не меняется.

### Проверки, когда дойдёт до реализации

- Уникальная замена меняет только этот фрагмент. Соседний `<script>` остаётся байт в байт.
- Пустой `new` вырезает `old`.
- Ноль совпадений — `patch_not_found`, документ тот же.
- Два одинаковых абзаца — `patch_ambiguous`, документ тот же. Повтор с более длинным `old` проходит.
- Пустой `old` — `bad_request`.
- Результат длиннее лимита — `limit_exceeded`, документ тот же.
- Нет документа — `not_found`.
- Верный `hash` записывает. Чужой `hash` — `conflict`, документ тот же.
- `old` равен `new` — успех без новой записи.
- В ответе нет поля `html`.
- Имя с хвостовым `.html` находит тот же документ.

## Другие идеи

Их можно делать независимо от `patch_document`.

- **Чтение куском.** `get_document` умеет ответить без тела: заголовки, размер, хеш. Отдельный аргумент возвращает диапазон или текст вокруг места правки. Полный HTML запрашивается, только когда правка без ориентира не находится. Это снимает входные токены, которые точечная замена не снимает.
- **Хеш и на полной замене.** Запись HTML тоже принимает `hash` и отказывает при устаревшем снимке. Полная перезапись не затирает более новую правку. Имеет смысл вместе с полем `hash` у `get_document`, даже если `patch_document` ещё нет.
- **Не эхо.** Ответы записи не содержат HTML. В инструкциях сервера прямо сказано не вставлять страницу в чат и не писать её в репозиторий пользователя. Повторное чтение в том же ходе после своей записи не нужно: тело ещё у модели.
